# MoE Profiling

`MoE_profiling` is an experimental workspace for analyzing expert load distributions from MoE routing results and evaluating how routing imbalance changes with batch size.

The repository includes experiments on:

- expert load distributions
- routed-token distributions
- imbalance ratios
- Gumbel approximations
- Gaussian approximations
- saddlepoint approximations
- capacity-aware distributions
- EP/PP tradeoffs
- latency proxies with expert correlation

The repository is organized into three main components:

- `experiments/`
  - Contains the actual experiment source code
  - Scripts are grouped by experiment type
- `expert_selections/`
  - Contains the profiling logs used as experiment inputs
  - Layer-wise expert selections are stored in `.jsonl` files
- `output/`
  - Contains figures, CSV files, and text summaries generated by the experiments

Unlike the earlier layout, the experiment scripts are now physically organized under `experiments/`.
There are no symbolic links to copies in the repository root.

## Data: `expert_selections/`

This directory contains the input profiling data used by the experiments.

The filename pattern is:

```text
expert_selection_openai_gpt-oss-20b_wikitext_103_ep{EP}_bs{BS}_{TIMESTAMP}_layer{LAYER}.jsonl
```

Examples:

```text
expert_selection_openai_gpt-oss-20b_wikitext_103_ep4_bs1_20260401_214455_layer0.jsonl
expert_selection_openai_gpt-oss-20b_wikitext_103_ep4_bs32_20260402_085953_layer23.jsonl
```

The filename fields indicate:

- `gpt-oss-20b`: model used for profiling
- `wikitext_103`: input dataset
- `ep4`: expert parallel degree
- `bs32`: actual batch size used when collecting the log
- `20260402_085953`: collection timestamp or run identifier
- `layer23`: routing result for the corresponding layer

Currently available profiling data:

- Model: `gpt-oss-20b`
- Dataset: `wikitext_103`
- EP: `4`
- Batch sizes: `1, 2, 4, 8, 16, 32`
- Layers: `0` through `23`, for a total of 24 layers

In other words, the current dataset contains routing logs for 24 layers under `EP=4`, collected across multiple batch sizes.

### JSONL Format

Each line in a profiling file is a JSON array.

The current logs mainly store `top_k=4` expert indices per token:

```json
[31, 21, 22, 6]
[4, 3, 5, 9]
[30, 27, 9, 3]
```

The analysis scripts support both of the following formats:

- Nested format:
  `[[e1, e2, e3, e4], [e1, e2, e3, e4], ...]`
- Flattened format:
  `[e1, e2, e3, e4, e5, ...]`

Common assumptions used throughout the experiments are:

- Total number of experts: `32`
- `top_k`: `4`
- Number of layers: `24`
- With `EP=4`, each GPU is assigned `32 / 4 = 8` experts

Many experiments convert token-level expert selections into GPU load patterns.

For example, under `EP=4`, the expert selection

```text
[3, 7, 10, 28]
```

is converted into the per-GPU routed-token pattern

```text
(2, 1, 0, 1)
```

## Experiment Code: `experiments/`

All experiment source code is stored under `experiments/`.

The scripts are grouped into three categories:

- `00_initial/`
  - Initial probability, distribution, correlation, and imbalance analyses
- `10_gumbel/`
  - Gumbel-based fitting and prediction experiments
- `20_extended/`
  - Extended experiments including routed-token convolution, capacity-aware analysis, Gaussian/saddlepoint approximations, EP/PP tradeoffs, and latency modeling

These files are the actual source files, not symbolic links.

## `experiments/00_initial`

This directory contains early exploratory and baseline experiments.

The main focus is on expert selection probabilities, routing distributions, correlations, and how imbalance changes with batch size.

Typical scripts include:

- `calculate_prob.py`
  - Initial probability calculations and heatmap/line-plot generation
- `calculate_real_expert_prob.py`
  - Computes expert selection probabilities directly from routing logs
- `count_expert.py`
  - Computes layer-wise expert probabilities and combination-based distributions
- `count_expert_correlation.py`
  - Computes correlation between jointly selected experts
- `plot_expert_correlation.py`
  - Visualizes expert correlations as heatmaps
- `compare_expert_distributions.py`
  - Compares expert distributions across different batch sizes or conditions
- `compare_token_distribution.py`
  - Builds token-level GPU-pattern PMFs from `bs=1` data and predicts larger-batch distributions through exact convolution
- `plot_distribution_overlay_bs_1_2_4_8_16_32.py`
  - Overlays distributions for multiple batch sizes in a single figure
- `predict_imbalance_ratio_from_bs1.py`
  - Predicts imbalance ratios using `bs=1` routing data
- `plot_imbalance_ratio_p95.py`
  - Visualizes imbalance ratios and p95 statistics
- `plot_best_case_prob.py`
  - Visualizes best-case probability results
- `plot_result.py`
  - Auxiliary visualization script for early experiment results

## `experiments/10_gumbel`

This directory contains experiments that use Gumbel approximations for max-load modeling.

Several scripts use `scipy.stats.gumbel_r` to fit or predict the distribution of maximum expert or GPU load.

Typical scripts include:

- `plot_actual_vs_gumbel.py`
  - Compares actual distributions against Gumbel approximations
- `plot_actual_vs_gumbel_layerwise.py`
  - Performs layer-wise Gumbel fitting and comparison
- `plot_actual_vs_gumbel_spike_removed.py`
  - Repeats Gumbel fitting after removing specific spikes
- `plot_actual_vs_gumbel_loadaware.py`
  - Applies a load-aware scoring rule instead of a simple maximum
- `plot_gumbel_expert_max_fixed_product.py`
  - Compares expert-max distributions under a fixed `EP * PP`
- `plot_gumbel_expert_max_per_layer.py`
  - Evaluates per-layer expert-max distributions using Gumbel fitting

## `experiments/20_extended`

This directory contains experiments that extend the initial exact-distribution and Gumbel-based analyses.

Typical scripts include:

- `count_expert_tokens.py`
  - Computes token-level GPU dispatch-pattern PMFs and exact-convolution-based distributions
- `analyze_routed_token_spikes.py`
  - Analyzes spike behavior in routed-token max distributions
- `compare_capacity_aware_distribution.py`
  - Compares distributions using capacity-aware scoring or penalties
- `plot_distribution_comparisons.py`
  - Reads comparison CSV files and generates summary plots
- `plot_ep_pp_tradeoff.py`
  - Visualizes EP/PP tradeoffs
- `predict_latency_with_expert_correlation.py`
  - Evaluates latency proxies while accounting for expert correlation
- `sweep_ep_degrees_from_fixed_routing.py`
  - Sweeps EP degree under a fixed-routing assumption
- `plot_actual_vs_saddlepoint.py`
  - Compares actual distributions against saddlepoint approximations
- `plot_ep_pp_tradeoff_saddlepoint.py`
  - Evaluates EP/PP tradeoffs using saddlepoint approximations
- `plot_fixed_ep_pp_budget_saddlepoint.py`
  - Studies fixed EP/PP budgets using saddlepoint approximations
- `sweep_ep_degrees_gaussian.py`
  - Sweeps EP degree using a Gaussian approximation
- `sweep_ep_degrees_saddlepoint.py`
  - Sweeps EP degree using a saddlepoint approximation

## Experiment Workflow

The overall workflow can be summarized as follows:

1. Read layer-wise routing logs from `expert_selections/`.
2. Convert token-level expert selections into GPU load patterns.
3. Compute actual distributions directly, or construct larger-batch distributions from PMFs obtained from `bs=1`.
4. Compare predicted or exact distributions against actual routing distributions.
5. Apply approximation methods such as Gumbel, Gaussian, or Saddlepoint.
6. Evaluate derived metrics such as imbalance ratio, p95, or latency proxy.
7. Save figures, CSV files, and summaries under `output/`.

## Running Experiments

Most scripts assume paths relative to the repository root, such as:

```text
./expert_selections
./output/...
```

Therefore, the recommended way to run an experiment is from the repository root.

For example:

```bash
cd MoE_profiling
python experiments/00_initial/compare_token_distribution.py
```

or:

```bash
python experiments/10_gumbel/plot_actual_vs_gumbel.py
```

Some scripts may import utilities or functions from other experiment scripts, so keeping the current directory structure unchanged is recommended.
